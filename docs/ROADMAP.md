# Delivery and graduation criteria

| Audit sequence | 0.3 outcome | Next evidence required |
|---|---|---|
| Correct defects | Unsupported capture configuration removed; deployment rules conditional; generated paths unified | Regression suite on supported systems |
| Safe setup | Preview/apply, ownership, conflict refusal, retained user docs/hooks/index, upgrade/removal | Real adoption feedback and additional fixtures |
| Compact contract | Short AGENTS.md, task tiers, progressive skills, conditional overlays | Comparative task outcomes |
| Verification | Real command/output/exit status with revision and tree binding | CI and user-flow evidence for each adopting project |
| Knowledge | Private derivatives, source hashes, stale/deleted states, correction history | Domain-specific citation/extraction evaluation |
| Capture | Explicit input/identity, private immutable records, safe retries/concurrency | Repeated manual use before any exit automation |
| Effectiveness | Reproducible fixtures, trial schema, protocol, result aggregation | Repeated controlled model runs; no outcome claims yet |
| Orchestration | Reassessed and deferred | Demonstrated handoff cost plus dependable task contracts |

Automatic capture should graduate only after manual capture reliably retains consequential
facts, omits noise/secrets, and handles corrections. A proposed adapter must establish a real
Codex lifecycle API, exact session identity, failure visibility, retries, cost bounds, and
concurrent-session tests. Until then, the explicit skill is the supported product.

Control Center should graduate only when measured handoff overhead exceeds maintenance cost.
Start with one authorized dispatch and structured result; test failure/cancellation/resumption
before fan-out. Parallel writers need isolation and integration checks. Host tool availability
must be probed and versioned; no guessed Workflow equivalent. External actions remain governed
by user authorization. Fewer human turns alone is not success if rework or mistakes increase.

Cross-model effectiveness is an empirical question. Keep ordinary/compact/full baselines and
publish failures, overhead, and uncertainty along with successful runs. Do not claim the framework
fixes a model's reasoning limitations based on deterministic helper tests.
